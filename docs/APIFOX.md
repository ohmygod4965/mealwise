# 用 Apifox 检测本项目

> 本机已安装 Apifox（进程在跑）。这里给两样东西，导入后**一键跑通全部接口**。

## 1. 两个可直接导入的文件

| 文件 | 类型 | 用途 |
|---|---|---|
| [mealwise.postman_collection.json](./mealwise.postman_collection.json) | Postman v2.1 集合 | **推荐**：6 个分组 / 21 个请求，已内置 token 自动串联与断言 |
| [openapi.json](./openapi.json) | OpenAPI 3 | 从运行中的服务导出（13 个 path），用于生成接口文档或代码 |

> `openapi.json` 是 `/v3/api-docs` 的实时导出，字段与代码一致。

## 2. 导入步骤（Apifox）

### 2.1 导入集合

1. Apifox → 左侧「项目」→ 新建项目（如 `Mealwise`）
2. 右上「导入」→ 选 **Postman** → 拖入 `mealwise.postman_collection.json`
3. 导入后能看到 6 个分组：

```
00 健康检查
01 认证          ← 先跑这个，token 会自动写进环境变量
02 食物库
03 餐次与热量
04 日记录
05 异常与鉴权
```

### 2.2 配置环境

「环境管理」→ 新建环境 `本地`，添加变量：

| 变量 | 值 |
|---|---|
| `baseUrl` | `http://localhost:8080` |
| `token` | （留空，登录后自动写入） |
| `mealId` / `itemId` / `foodId` | （留空，跑流程时自动写入） |

选中该环境后再发请求。

### 2.3 跑测试

- **单步**：先点「01 认证 → 登录」，看到 `token 已写入环境变量` 后，其余请求直接点发送即可
- **一键**：右上「运行」→ 选整个集合 → 顺序执行，看断言面板的 绿/红

## 3. 集合里的自动化逻辑

| 请求 | 后置脚本做什么 |
|---|---|
| 登录 | `pm.environment.set("token", body.data.token)` —— 后续请求自动带 `Bearer {{token}}` |
| 食物分页 | 把第一条食物 id 存进 `foodId` |
| 创建餐次 | 存 `mealId` |
| 添加食物项 | 存 `itemId` |

断言覆盖：HTTP 状态 + `code` 一致 + 关键业务字段（token 存在、热量 > 0、建议 ≤ 3 条且同类别、lower 的 delta < 0、404/400/401 语义）。

## 4. 我已经跑过的等价检测（只读，未写数据）

在本机用同一套请求顺序跑了一遍（不创建数据），**29 项断言全通过**：

```
00 健康检查   OpenAPI 200 / 13 个 path / X-Trace-Id 存在 / 前端首页含 #app
01 认证       登录 200 / token 长度正常 / /users/me 200 / profileComplete 字段存在
02 食物库     分页 200 / 字段完整 / 搜索命中「米饭」/ 删除不存在 → 404 且响应体统一
03 餐次       热量 200 / 合计与明细一致 / 数值 1 位小数 / higher 200 / 每组 ≤3 且同类别
               lower 200 且 delta 为负 / 非法策略 → 400
04 日记录     200 / 日期格式正确 / targets 与 comparison 同时有值或同时为空
05 鉴权       无 token → 401 / 他人访问我的餐次 → 403
```

结论：**服务当前可用**，接口契约与文档一致。

## 5. 常见问题

**Q：登录请求 200 但后续请求 401？**
环境里 `token` 没写进去。检查：① 是否选了环境；② 登录请求的「后置脚本」是否被删；③ 是否用了「导入示例」而不是导入集合。

**Q：`{{mealId}}` 为空导致 URL 变成 `/api/meals//items`？**
先跑「03 餐次 → 创建餐次」，它会写 `mealId`。

**Q：跑完发现数据变多了？**
集合里「新增食物」「创建餐次」「添加食物项」会真实写库。只想检测可用性，用只读流程（00/01/02 的部分 + 04/05）即可。

**Q：想连别的环境？**
改环境变量 `baseUrl` 即可（例如 Docker 的 `http://localhost:8080` 或局域网 `http://10.167.168.18:8080`）。

**Q：能不能接 CI？**
Apifox 支持导出 CLI 命令（`apifox run`），需要先在 Apifox 云端建项目并拿 Access Token；本机这套集合也能被 `newman` 直接跑。
