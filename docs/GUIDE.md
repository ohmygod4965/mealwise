# Mealwise 说明文档

> 面向"用这个系统的人"：怎么跑起来、每个页面干什么、数字是怎么算出来的、遇到问题怎么排查。
> 想改代码看 [README](../README.md)，想对接接口看 [API.md](./API.md)。

---

## 1. 这是什么

**一句话**：记录一餐吃了什么、多少克，自动算热量与三大营养素，并在**同类别食物**里给出"换成什么更合适"的建议。

它解决的是三个具体问题：

| 问题 | Mealwise 的做法 |
|---|---|
| "我吃了一碗米饭，到底多少卡？" | 按每 100g 营养值 × 实际克数实时换算，不用自己算 |
| "想多吃点，吃什么能加得合理？" | 同类别内找热量稍高的选项，按差异温和排序，而不是推一个热量爆炸的 |
| "今天吃够了吗？" | 用你的性别/身高/体重算出建议摄入，和当天合计逐项对比 |

## 2. 三个入口

| 入口 | 地址 | 适合 |
|---|---|---|
| 桌面 Web | `http://localhost:8080` | 日常记录、看表格 |
| 手机浏览器 | `http://<局域网IP>:8080` | 在厨房/饭桌上随手记（已做移动适配） |
| 微信小程序 | `mealwise-miniprogram/`（需开发者工具导入） | 微信内使用；真机预览需自己的 AppID |

三个入口**共用同一个后端与账号体系**，数据实时一致。

## 3. 5 分钟跑起来

### 3.1 前置

- JDK 17+
- MySQL 5.7 或 8.0（默认连接 `root/123456`，可改 `application-dev.yml`）
- 首次运行需要初始化数据库

### 3.2 一键启动（Windows）

```powershell
cd mealwise
.\start-local.ps1
```

脚本会依次：检测 MySQL → 缺库则执行 `docs/init.sql` → 缺 jar 则构建 → 启动 → 打开浏览器。

### 3.3 手动启动

```powershell
mysql -u root -p123456 < docs\init.sql
mvn -f mealwise-server\pom.xml -DskipTests package
java -jar mealwise-server\target\mealwise-server-1.0.0.jar --spring.profiles.active=dev
```

> 若报 `Unable to create tempDir`，说明系统临时目录不可写，加 `-Djava.io.tmpdir=<可写目录>`。

### 3.4 Docker

```bash
mvn -f mealwise-server/pom.xml -DskipTests package
docker compose up --build
```

## 4. 使用手册

### 4.1 食物库（`/foods`）

- 顶部可 **按名称搜索**、**按类别筛选**、分页浏览
- 表格列：食物 / 类别 / 热量 / 蛋白质 / 脂肪 / 碳水 / 过敏原 / 状态 / 操作
- 「新增食物」填表即可（营养值都是"每 100g"口径）
- 「删除」是**软删除**：列表里消失，但历史餐次仍能正常计算

> 移动端：表格会自动隐藏「过敏原/状态」列；超窄屏再隐藏「类别」，避免横向挤压。

### 4.2 记录一餐（`/meals`）

1. 选餐次：早餐 / 午餐 / 晚餐 / 加餐
2. 搜索食物 → 选中 → 填克数 → 添加
3. 表格里可 **直接改克数**、**删除某项**
4. 右侧实时显示这一餐的 **热量 / 蛋白质 / 脂肪 / 碳水**
5. 底部可以「查看替换建议」，或「保存并查看今日记录」

> 餐次在**加入第一个食物时**才真正创建，避免产生一堆空餐。
> 每改一次克数，合计立刻重算——热量从不缓存。

### 4.3 替换建议

- 顶部切换策略：`higher`（多吃点）/ `lower`（控制热量）
- 按食物项分组，每组最多 3 条建议，卡片显示：原食物 → 建议食物、预计增减热量、一句理由
- 例：`同为「主食」，每 100g 比「米饭」高 42.0 kcal；按 200g 计，替换后多摄入约 84.0 kcal`
- 没有候选时显示提示（**这不是报错**，只是同类里没有更合适的）

### 4.4 今日记录（`/day`）

- 顶部日期选择：默认今天，可回看历史；非今天时出现「回到今天」
- 按 **早餐 / 午餐 / 晚餐 / 加餐** 分区，每餐显示时间、明细、小计
- 右侧「今日摄入 vs 建议」：4 条进度条 + 差值 + 状态标签
- 没填身体资料时显示引导卡片，点「去填写」补资料

### 4.5 我的资料

右上角头像 →「我的资料」，填 **性别 / 身高 / 体重 / 年龄**（年龄可留空）。

保存后「今日记录」的建议摄入与对比立即刷新。

---

### 4.6 AI 饮食推荐（`/ai`）

1. 左栏选目标（减脂 / 维持 / 增肌）、可选填目标热量、勾选要安排的餐次
2. 可填口味偏好（如「想吃中餐、少油」）和额外忌口（会与账号过敏原合并）
3. 点「生成 AI 方案」，等待 10–30 秒（大模型生成 + 逐样联网核验）
4. 右栏出现：方案说明、总热量与三大营养素、每餐明细
5. 每样食物右侧标注来源：**本地食库**（最可信）/ **联网核验**（Open Food Facts，可点开商品页）/ **模型估算**
6. 不满意点「重新生成」

> 没配置密钥时不会报错，页面显示「本地规则兜底」并给出三餐参考；方案只作参考，不构成营养处方。
## 5. 几个概念

| 概念 | 含义 | 注意 |
|---|---|---|
| **食物（Food）** | 食物库里的标准条目，营养值以**每 100g** 记录 | 全局共享，所有登录用户可维护 |
| **餐次（Meal）** | 一次用餐，属于某个人、某个时间、某个餐次类型 | 数据隔离边界是 `meal.user_id` |
| **食物项（Meal Item）** | 餐次里的一行：哪个食物 + 多少克 | 同一餐可以出现两条相同食物（两份鸡胸） |
| **日记录（Day）** | 某一天所有餐次的**聚合视图** | 不单独存表，实时按天查询汇总 |
| **替换策略** | `higher` 找更高的，`lower` 找更低的 | 只允许这两个值，写错直接 400 |
| **达成率** | 当日摄入 ÷ 建议摄入 × 100% | 85%~115% 记为"达标" |

## 6. 数字是怎么算的

### 6.1 单项营养

```
某项热量 = 食物热量(每100g) × 克数 ÷ 100
```

蛋白质 / 脂肪 / 碳水同理。**全程高精度，最后一步才保留 1 位小数**——避免"每项先四舍五入再相加"与"先相加再四舍五入"差 0.1。

### 6.2 每日建议摄入

用 **Mifflin-St Jeor** 公式估算基础代谢：

```
男：BMR = 10×体重kg + 6.25×身高cm − 5×年龄 + 5
女：BMR = 10×体重kg + 6.25×身高cm − 5×年龄 − 161
TDEE = BMR × 1.375      ← 轻度活动系数
```

三大营养素按"维持体重"分配：

| 项 | 规则 |
|---|---|
| 蛋白质 | 1.5 g / kg 体重 |
| 脂肪 | 占总热量 25%（÷ 9 kcal/g） |
| 碳水 | 剩余热量 ÷ 4 kcal/g |

示例（男 175cm / 70kg / 30 岁）：

```
BMR  = 10×70 + 6.25×175 − 5×30 + 5 = 1648.75  → 展示 1648.8
TDEE = 1648.75 × 1.375 = 2267.03              → 建议 2267.0 kcal
蛋白 = 70 × 1.5 = 105.0 g
脂肪 = 2267 × 25% ÷ 9 = 63.0 g
碳水 = (2267 − 105×4 − 63×9) ÷ 4 = 320.0 g
```

页面上会同时展示**公式与假设**（年龄缺省按 30、活动系数 1.375），这些数字不是黑箱。

### 6.3 为什么推荐按"热量差升序"

如果直接取"热量最高的同类食物"，结果往往是「米饭 → 五花肉」这种没法执行的建议。
按 `|差值|` 升序 = 优先生效差异温和的替换：更容易接受，也更容易解释"为什么是它"。

## 7. 常见问题

**Q1：为什么建议摄入是灰色的 / 显示"先完善身体信息"？**
没填性别/身高/体重时，后端不会猜一个默认体重给你算，`targets` 返回 `null`。去「我的资料」填完即可。

**Q2：为什么某道菜没有替换建议？**
可能原因：同类里没有热量更高（或更低）的食物、候选都被你的过敏原过滤掉了、或候选已下架。页面会给出对应提示。

**Q3：删掉食物后，昨天的餐次会不会算错？**
不会。删除是软删除，历史餐次仍按当前食物数据计算；如果食物被永久删除（数据库层不允许，外键 RESTRICT 会拦住）。

**Q4：改了克数，之前的热量记录会变吗？**
会。热量是实时算的，不存快照——这是刻意的设计（见 README 6.2）。

**Q5：为什么没有"删除某一餐"？**
当前以"餐次 + 食物项"为单位维护，删除整餐可以逐项删。整餐删除接口未做（见限制）。

**Q6：登录过期了怎么办？**
token 24 小时有效，过期后任何接口返回 401，前端会自动清登录态并跳回登录页，重新登录即可。

**Q7：手机打不开后端地址？**
① 手机与电脑是否同一 Wi-Fi；② IP 是否填对（`ipconfig` 看 WLAN IPv4）；③ Windows 防火墙是否放行 8080。

**Q8：小程序报"不在以下 request 合法域名列表"？**
开发者工具「详情 → 本地设置」勾选「不校验合法域名…」。上线则必须换成 https + 备案域名。

**Q9：数据存在哪？怎么清空重来？**
MySQL 的 `mealwise` 库。重跑 `docs/init.sql` 会 **DROP 并重建 4 张表**，然后重新注册账号即可。

**Q10：为什么日志里有一串 `traceId`？**
每个请求生成/透传一个 id，写进日志与响应头。用户报错时贴截图，用这个 id `grep` 就能定位整条链路。

## 8. 运维要点

### 8.1 配置项

| 配置 | 位置 | 说明 |
|---|---|---|
| 数据库连接 | `application-dev.yml` / 环境变量 `DB_*` | 生产用 `application-prod.yml` |
| JWT 密钥 | `jwt.secret` / `JWT_SECRET` | **至少 32 字节**，生产必须覆盖 |
| 端口 | `server.port`（默认 8080） | |
| 文档开关 | `knife4j.enable` | 生产默认关闭，避免暴露接口 |

### 8.2 日志

- 位置：启动时指定的输出（本机启动脚本写到 `.run/app.log`）
- 格式带 `[traceId]`，可按请求串联
- 未预期异常会记完整堆栈，但对外只返回 `系统繁忙，请稍后重试`

### 8.3 备份

只需备份 MySQL 的 `mealwise` 库；前端与后端都是无状态可重建产物。

```bash
mysqldump -u root -p mealwise > backup.sql
```

## 9. 已知边界

| 项 | 现状 |
|---|---|
| 无 refresh token | 24h 单 token，过期需重新登录 |
| 食物库无角色权限 | 所有登录用户可增删改（真实项目应加 role） |
| 无整餐删除接口 | 只能逐项删除 |
| 无组合优化推荐 | 逐项推荐，不做"整餐最优组合"（NP 问题，收益不明确） |
| 活动系数固定 1.375 | 未提供久坐/中度/高强度切换 |
| 小程序未做运行时验证 | 本机无微信开发者工具，仅语法与连通性验证 |
| Docker 未在本机实测 | 本机未安装 Docker，compose 按标准编写 |
